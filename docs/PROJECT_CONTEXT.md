# Контекст expenseBot

Последняя сверка с исходниками: 2026-10-05. Это краткая памятка для будущих сессий; детали проверяй в коде нужного модуля.

## Назначение и стек

Telegram-бот для учёта и анализа расходов. Go 1.25.1 по `go.mod`, PostgreSQL через `pgx/v5`, Telegram API через `go-telegram-bot-api/v5`. Конфигурация YAML, логирование через `log/slog`. Есть поддержка системной службы через `kardianos/service` и Docker.

## Карта исходников

- `cmd/bot/main.go` — точка входа, загрузка конфигурации, база, выбор обычного запуска или службы; команды `install` и `uninstall`.
- `internal/app/bootstrap.go` — сборка зависимостей: репозитории → сервисы → сценарии → обработчик Telegram; регистрация фоновых заданий.
- `internal/app/app.go` — запуск приложения и планировщика.
- `internal/bot` — обработчик Telegram и клавиатуры.
- `internal/flow` — сценарии меню, счетов, транзакций и отчётов. Файл отчётов сейчас называется `repot_flow.go`.
- `internal/service` — прикладная логика пользователей, счетов, сессий, валют, транзакций, отчётов и курсов.
- `internal/repository` — работа с PostgreSQL; `internal/model` — структуры данных.
- `internal/scheduler` — ежедневные и ежемесячные отчёты, получение курсов, почасовое логирование.
- `internal/config`, `internal/filesystem`, `internal/logger` — настройки, пути и логи.
- `internal/platform`, `internal/servicehost` — поддержка службы Windows/Linux.
- `internal/exchangerate`, `internal/dateutil`, `internal/userstate` — вспомогательные модули.

## Запуск и проверки

Из корня проекта:

```powershell
go build -o expenseBot.exe ./cmd/bot
go test ./...
go vet ./...
go run ./cmd/bot
```

Последняя команда запускает реального бота; нужны доступные PostgreSQL и Telegram, заполненный `config.yaml` и подготовленная схема БД. Эти команды при подготовке памятки не выполнялись; работоспособность окружения не проверена. Добавлены модульные тесты проверки валют и обработки ответов API в `internal/service/currency_test.go` и `internal/exchangerate/exchange_rate_test.go`; они не подключаются к PostgreSQL и Telegram.

Поля конфигурации по `internal/config/config.go`: `log_config` (`folder`, `level`, `console`, `file`), `database.url`, `bot_key`, `bot_proxy`, `app_name`. Секретные значения здесь не хранить.

Dockerfile собирает Linux amd64 бинарник и запускает его в Debian. `docker-compose.yml` описывает бота, VPN Amnezia и SOCKS5-прокси; PostgreSQL в этом compose не определён. VPN требует `awg_conf/wg0.conf`. Для контейнера бота задан часовой пояс `Europe/Moscow`.

## Известные нюансы

- Флаг `-config` объявлен в `main.go`, но `config.Load(fileName)` не использует аргумент и ищет файл с фиксированным именем `config.yaml`.
- При обычном запуске существующий `config.yaml` ищется в рабочей папке; иначе, а также для службы, используется папка исполняемого файла.
- Если конфигурация отсутствует, загрузчик пытается записать значения по умолчанию и возвращает исходную ошибку; `main` завершает запуск через panic.
- На момент осмотра папка `migrations` пустая. Источник схемы БД и способ её развёртывания ещё не установлены.
- `.gitignore` исключает в том числе `*.yaml`, `*.exe`, `*.mod`, `*.sum`, `*.png`, `*.txt`, `/db_bak` и `/awg_conf`. Наличие файла на диске не означает, что он хранится в Git.
- В рабочей папке есть `expenseBot.exe`, `Logs` и `db_bak`; актуальность бинарника и содержимое логов/резервных копий не проверялись.

## Решения пользователя

- 2026-10-05: хранить знания о проекте в репозитории, чтобы будущие сессии Codex начинали работу без повторного полного исследования. `AGENTS.md` задаёт порядок работы, этот файл хранит актуальный контекст.

- 2026-10-05: новую валюту проверять по ответу API курсов до создания счёта. Сохранять только запрошенную валюту и её курс одной транзакцией, с датой из API, как в ночном задании. Все валюты из API в базу не добавлять. Если у существующей валюты нет курса в последнем наборе (по максимальной дате в БД), получать его также при вводе и выборе кнопкой. USDT остаётся равным USD.
- Неподдерживаемая валюта: «Валюта XXX не найдена в источнике курсов. Проверьте код или введите другую валюту». Недоступность API: «Не удалось проверить валюту. Попробуйте ещё раз позже». При этих ошибках счёт не создаётся; состояние сбрасывается в idle по прежнему подходу сценария.
- Сохранение курса повторяемо: запись с той же датой и кодом заменяется в транзакции. Запросы пользователя и ночное задание используют общую PostgreSQL advisory-блокировку по коду валюты. Миграция схемы не требуется; проверка на реальной БД не выполнялась.
